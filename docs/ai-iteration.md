# След ключевой итерации с ИИ: этап 3, запись и защита от повторной записи

Ключевая итерация — этап 3 из `PLAN.md`: именно здесь проверяется главное требование `spec.md` о том, что занятый слот нельзя занять второй раз.

## 1. Задача агенту

> Этап 3 из PLAN.md: у свободного слота — поле ФИО и кнопка записи. Сервер проверяет непустое ФИО и занимает слот одной атомарной операцией; для занятого слота возвращает понятный конфликт и не меняет исходную запись. Работай по spec.md и AGENTS.md.

## 2. План агента до изменения

* Файлы: `src/db.js`, `server.js`, `public/index.html`, `public/app.js`, `public/styles.css`.
* Ожидаемый эффект: у свободных слотов появляется форма записи; `POST /api/bookings` занимает слот или возвращает 409 с текстом «Слот … уже занят: ФИО. Выберите другой свободный слот.».
* Способ проверки: запросы к API — запись, повторная запись, пустое ФИО, несуществующий слот, некорректный запрос, три одновременных запроса на один слот; затем ручная проверка в двух вкладках браузера.

## 3. Что сделал агент

Запись — одна операция обновления, которая меняет только свободный слот:

```sql
UPDATE walk_slots
SET booked_by = ?, booked_at = ?
WHERE walk_date = ? AND slot_time = ? AND booked_by IS NULL
```

Если обновлено 0 строк, слот уже занят: сервер отвечает 409, называет ФИО из базы и возвращает актуальные слоты, чтобы страница перерисовалась. Отдельного чтения «свободен ли слот» перед записью нет — `spec.md` это запрещает.

ФИО очищается от лишних пробелов; пустое ФИО и ФИО длиннее 100 символов отклоняются с кодом 400.

## 4. Проверка агента

| Проверка | Ожидание | Факт |
|---|---|---|
| Запись «Анна Тестова» в `09:00` | 200, слот занят | 200 |
| Повторная запись «Илья Примеров» в `09:00` | 409, в слоте «Анна Тестова» | 409, «Слот 09:00 уже занят: Анна Тестова…» |
| ФИО из пробелов | 400 | 400, «Введите ФИО.» |
| Несуществующий слот `10:00` | 400 | 400, «Такого слота нет.» |
| Некорректный JSON | 400 | 400 |
| Три одновременных запроса на `15:00` | один 200, два 409 | 200, 409, 409 |

По ходу проверки агент заметил, что одно сообщение об ошибке было без точки в конце, в отличие от остальных, и выровнял их.

## 5. Проверка студентом

В браузере на `http://localhost:3000`:

* запись «Илья Примеров» на `13:00` — появилось «Вы записаны на 13:00.», слот стал серым с ФИО;
* вторая вкладка открыта до записи; в первой «Анна Тестова» записалась на `17:00`, во второй «Илья Примеров» попытался на `17:00` — красный отказ с ФИО «Анна Тестова», слот перерисовался как занятый;
* ФИО из пробелов — «Введите ФИО.»;
* ошибок в консоли нет.

## 6. Решение

Изменение принято: результат совпал с DoD 3 и DoD 4. Статус этапа и результат проверки записаны в `PLAN.md`, изменение закоммичено.
