# «Кто выгуливает Бориса»

Учебный Node.js micro-MVP для вымышленной компании «Догяндекс». Общая страница, на которой сотрудники записываются на прогулку с псом Борисом и видят, кто кормил его последним.

Требования к продукту — в `spec.md`, правила работы с ИИ-агентом — в `AGENTS.md`, этапы и проверки — в `PLAN.md`. Этот файл описывает фактическое состояние проекта.

## Статус

Все семь DoD из `spec.md` выполнены и проверены вручную, результаты проверок — в `PLAN.md`.

## Запуск

Нужен Node.js 22.13 или новее (проверено на 24.13). Внешних зависимостей нет: SQLite встроен в Node.js, поэтому `npm install` не нужен.

```
npm start
```

Откройте `http://localhost:3000`. Порт можно поменять переменной окружения `PORT`. База хранится в файле `data/boris.sqlite` и создаётся при первом запуске; папка `data/` не попадает в репозиторий. Чтобы начать с чистого состояния, остановите сервер и удалите `data/boris.sqlite`.

## Главный сценарий

Проверяется на синтетических данных, например «Анна Тестова» и «Илья Примеров».

1. Открыть `http://localhost:3000`.
2. Увидеть текущую дату и пять слотов: `09:00`, `11:00`, `13:00`, `15:00`, `17:00`.
3. В свободном слоте ввести ФИО и нажать «Записаться».
4. Увидеть «Вы записаны на …»: слот стал серым и показывает ФИО.
5. Во второй вкладке, открытой до записи, попробовать занять тот же слот другим ФИО и получить отказ «Слот … уже занят: …». Исходная запись не меняется.
6. Обновить страницу, открыть приложение в другом браузере или перезапустить сервер — запись на месте.

Дополнительно: в карточке «Последнее кормление» ввести ФИО и нажать «Отметить кормление» — карточка покажет время и ФИО.

## Как устроено

* `server.js` — HTTP-сервер на `node:http`: отдаёт страницу и обрабатывает API.
* `src/db.js` — работа с SQLite через `node:sqlite` по схеме из `spec.md`.
* `public/` — страница: `index.html`, `styles.css`, `app.js`.

API:

* `GET /api/slots` — текущая дата и пять слотов; слоты на текущую дату создаются, если их ещё нет;
* `POST /api/bookings` с `{ "slotTime": "09:00", "name": "Анна Тестова" }` — запись; занятый слот — ответ 409;
* `GET /api/feedings/last` — последнее кормление;
* `POST /api/feedings` с `{ "name": "Илья Примеров" }` — отметить кормление.

Запись в слот выполняется одной операцией обновления, которая меняет только свободный слот, поэтому из одновременных запросов проходит ровно один.

При отказе в записи браузер пишет в консоль разработчика строку о статусе 409 (Conflict). Это ожидаемо: так браузер отмечает ответ сервера о конфликте, ошибкой приложения это не является.

## Границы

Входит:

* одна общая страница без регистрации и авторизации;
* пять фиксированных слотов только на текущую дату;
* запись в свободный слот по ФИО с защитой на сервере от повторной записи;
* SQLite как единственное хранилище состояния;
* карточка последнего кормления.

Не входит:

* авторизация, роли, личные кабинеты, справочник сотрудников;
* отмена и администрирование записей, уведомления, календарь на неделю, история действий;
* реальные ФИО, рабочие данные, секреты и внешние интеграции;
* деплой, масштабирование и production-grade надёжность.
